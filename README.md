## Лабораторная: Flutter, GitHub Actions, Supabase и Firebase

Проект использует общий Firebase- и Supabase-проект с основным сайтом, но
данные разделены: здесь таблица Supabase `students_masha` и узел Firebase
`students_masha`, поэтому записи не пересекаются с таблицей `students`.

### Базы данных

Supabase: таблица `students_masha`.

```sql
create table if not exists public.students_masha (
    id bigint generated by default as identity primary key,
    name text not null,
    specialty text not null,
    grad_year integer not null
);

alter table public.students_masha disable row level security;

do $$
begin
    if not exists (
        select 1
        from pg_publication_tables
        where pubname = 'supabase_realtime'
          and schemaname = 'public'
          and tablename = 'students_masha'
    ) then
        alter publication supabase_realtime add table public.students_masha;
    end if;
end $$;
```

Firebase: узел `students_masha` в Realtime Database. Правила:

```json
{
  "rules": {
    "students": {
      ".read": true,
      ".write": true
    },
    "students_masha": {
      ".read": true,
      ".write": true
    }
  }
}
```

Публичные ключи указаны в `js/supabase-config.js` и `js/firebase-config.js`.
Отключённый RLS и открытые правила допустимы только для учебной демонстрации с
вымышленными данными. `service_role`/`secret` ключи в проект не добавляются.

### Flutter-приложение

```bash
cd flutter_project
flutter pub get
flutter run
flutter build apk --release
dart analyze
flutter test
```

Готовый файл: `flutter_project/build/app/outputs/flutter-apk/app-release.apk`.
Идентификатор приложения — `com.example.college_app_masha`, поэтому оно
устанавливается рядом с основным College App и не заменяет его.

### Автоматическая сборка

При push в `main` workflow собирает release APK, публикует его как артефакт и
прикрепляет к GitHub Release с тегом `build-<номер запуска>`. Отдельные секреты
не нужны: используется `GITHUB_TOKEN` с правом `contents: write`.

### Ограничения

Текущий APK подписан тестовым ключом и подходит для демонстрации, но не для
публикации в RuStore. Для магазина нужен отдельный release keystore и хранение
паролей в GitHub Secrets.
